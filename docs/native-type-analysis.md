# 怎样区分格式、类型和答案正确性

v4的两组都先写依据再写答案。控制组沿用v3的不限字符提示，实验组仅多一句明确的原生JSON类型要求。题目本身已经要求数值或数组，所以这是“强化提醒”的实验，不是原来完全没写类型要求。

## 三道不同的检查

|响应示例（省略evidence）|JSON可解析|原生类型合格|答案正确|
|---|---|---|---|
|数值题返回`{"answer":"0.5"}`|是|否：是字符串|否|
|参考0.5，返回`{"answer":0.4}`|是|是：是number|否|
|参考0.5，返回`{"answer":0.5}`|是|是|是|
|数组题返回`{"answer":"[1,2]"}`|是|否：是字符串|否|
|参考`[1,2]`，返回`{"answer":[1,"2"]}`|是|外层array合格|否：元素类型错误|
|响应在JSON中途截断|不能作为完整响应|否|否|

原生类型端点仅检查最外层；number要求有限数字且排除布尔值。正式答案评分继续检查数组元素类型、顺序、内容与结构，以及每道数值题的原始容差。数组中本来要求字符串ID时，元素引号是正确的，不应被删除。

沿用项目已有解析规则：允许完整响应最外层的一对Markdown JSON代码围栏，去掉围栏后必须是完整JSON对象；不从混有额外说明的文本中搜索JSON。因此“可解析”不是“原始响应字节可直接交给json.loads”。v4没有改变这一规则。

“输出契约”是另一个指标：字段是否只有evidence和answer、依据是否非空字符串且在答案前。它不判断依据语义真实性，也不替代answer类型检查。本轮两组的契约相同，没有像v3那样存在不同长度要求。

## 错误构成如何对齐分母

`types.json`中的八类互斥状态为：请求失败、pending、未尝试、截断、非法JSON、原生类型错误、类型正确但答案错误、正确。每个模型/条件/范围内相加等于计划请求数，因而中断或缺失不会悄悄消失。

正确率和类型合格率则以返回请求为分母。两组配对比较只使用同模型、同题、同重复且双方返回的记录。图里的“完整计划构成”和“有效返回配对”不是同一个分母，两种都要保留。

类型指标改善而正确率不变，可能意味着模型从字符串错误变成了数字算错；也可能不同题目的改善与退步抵消。需要看逐对变化和互斥分类，不能只看汇总百分比。如果某组仅剩类型正确的回答，仍应把所有返回计入主分析，不事后筛掉坏格式。

## 为什么不用自动转型提高成绩

把`"0.5"`转成数字看起来容易，但模型也可能返回`"1/3"`、带单位文本或嵌套错误数组。修复规则会改变系统行为，既可能救回答案，也可能引入误解。要研究修复，应该提前固定允许的变换、拒绝规则、额外调用和成本。

v4没有执行修复，不会解析字符串里的数字或数组再重判。`wrong_type_string_ids`只帮助定位原始记录；实际正确数仍来自原始answer。多出的类型提醒本身消耗输入token，若改变响应长度，还会改变输出token，均按真实usage计入。

## 新题和区间的解释边界

16道题与前五轮没有完整prompt重复，12道生成数值题的参数也未重复。但家族仍是Bayes、macro-F1、数组变换和代码引用，因此只验证了新实例，没有跨领域验证。四道数组参考由人工检查，12道数值参考可由Fraction重算。

两次采样观察同题波动，不是把16题变成32道独立题。整体正确率差、类型合格率差及token节省区间按题ID聚类重采样2000次，但同一题型的参数变体也可能相关。区间没有多重校正，不能证明总体优势、等价性或不劣性。

## 离线复核

```bash
python -m peerlab analyze-efficiency examples/token-efficiency-v4/run.json --output runs/v4-recheck
python scripts/build_native_dataset.py --output runs/rebuilt-native-cases.json
# 可选matplotlib绘图
python scripts/plot_efficiency.py examples/token-efficiency-v4/run.json --output runs/v4-figures
```

`analysis.json`保留答案质量与用量配对，`dimensions.json`提供分层、稳定性、误差和延迟，`types.json`提供类型端点、互斥分类及原始ID。原始文件SHA256与执行commit在`provenance.json`，供应商返回内容在`run.json`；SHA256用于发现字节变化，并不是供应商对真实性的签名。
