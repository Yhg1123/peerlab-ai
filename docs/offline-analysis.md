# 下载原始记录后，独立复核实验

```bash
# 新的四组协议：默认比较普通互审与先解后审
python -m peerlab analyze runs/review-study-v1/run.json

# 首轮旧记录也可复核，显式选择已有条件
python -m peerlab analyze examples/pilot/run.json --left baseline --right peer --output runs/pilot-analysis
```

不需要密钥，不调用任何模型。产出 `analysis.json` 和 `analysis.md`。

## 先核验，再计算

工具重算题库hash，校验有oracle的参考答案，核对条件和请求次数，拒绝重复记录，检查v2调用依赖，然后从原始输出重新评分并比对已保存的判分。修改参考答案、误复制同一次回答或损坏依赖都会报错，而不是继续输出看似正常的统计。

这验证的是记录内部一致性。它不能证明服务商真的生成过这些文本；完全伪造一套相互一致的记录仍可能通过。不要把它称为真实性认证或不可篡改存证。

## 如何读配对表

左、右条件必须来自同一作者模型、同一道题、同一轮次。表中分别计数：

- 都对；
- 仅左边对；
- 仅右边对；
- 都错。

右减左的准确率差值为 `(仅右对 - 仅左对) / 有效配对数`。只要一边缺失，该对就单独记录为缺失，不放进分母。截断的回答仍算收到回答，但根据预设规则为未通过。

同时报告各任务类别，避免仅看总体掩盖不同题型的差异。不自动给出显著性或p值；同模板题目、重复采样和两模型回答间的相关性没有被假定为零。

## 成本为什么不能把每组相加

全程总量中，一个真实返回只计一次。每个条件的路径成本回答的是“获得该答案所依赖的调用有哪些”：

| 条件 | 每题每作者依赖的返回 |
|---|---|
| baseline | 作者独立答案 |
| self | 作者独立答案 + 自己审稿 + 作者修订 |
| peer | 作者独立答案 + 另一个模型审稿 + 作者修订 |
| peer_independent | 作者独立答案 + 审稿者独立答案 + 审稿 + 作者修订 |

先解后审复用已经产生的另一个baseline，因此实验增加的调用仍为每作者两次，但依赖路径有四个返回。共享的baseline会同时出现在不同路径内，路径成本不能相加当总消费。

Token字段缺失时明确报告未知数量。失败或超时可能产生费用，但没有可靠用量就不猜账单。调用延迟包含网络与服务端等待，不代表模型纯计算时长。
