# 类型要求写清楚后：128次请求的结果与代价

2026-10-04执行。**明确JSON原生类型提醒，在这批新实例上减少了类型错误；Kimi的配对正确数明显增加，DeepSeek的净收益较小。两者配对总token都增加。** 这不是模型能力排行榜，也没有测得实际账单或修复调用成本。

## 设计与证据

16题：6道Bayes、6道macro-F1、4道数组任务；每题2次采样、2模型、2条件，共128次请求。126次返回、2次Kimi网络失败，无重试或替补；已知用量38,089 token（输入17,784、输出20,305）。运行状态保留为`partial`。

控制组复用v3“先依据后答案、无明确字符上限”系统提示；实验组仅附加一句number/array原生类型提醒。题目原本已有类型要求，因此研究的是强化提醒的增量作用。温度0.6、thinking关闭、输出上限700 token，其他参数相同。请求和返回模型均为`deepseek-flash`、`kimi-k2.6`。

[执行前方案](token-efficiency-v4.md)、[机器计划](token-efficiency-v4-plan.json)、实现与题库均在真实调用前提交：[937a3a8](https://github.com/Yhg1123/peerlab-ai/commit/937a3a884c34e36e02736722b53e5c6e3fa23aeb)。新题与前五轮没有完整prompt重复，但仍属于已知题型，不是外部领域验证。

## 四组实际结果

每组计划32次。“正确”按原始answer严格判分：数值绝对误差≤1e-6，数组内容、类型、顺序、结构均须符合参考；不把字符串转型后重判。

|模型|条件|正确 / 返回 / 计划|返回正确率|原生类型合格 / 返回|输入token|输出token|总token|
|---|---|---:|---:|---:|---:|---:|---:|
|DeepSeek|控制|26 / 32 / 32|81.25%|30 / 32|3,926|3,859|7,785|
|DeepSeek|明确类型|28 / 32 / 32|87.50%|32 / 32|4,886|4,199|9,085|
|Kimi|控制|10 / 32 / 32|31.25%|11 / 32|4,184|6,239|10,423|
|Kimi|明确类型|25 / 30 / 32|83.33%|30 / 30|4,788|6,008|10,796|

Kimi明确类型组按完整计划算，正确响应交付为25/32（78.13%）；不能把2次失败抹掉。所有返回均有输入、输出和总用量；失败用量未知，未按0补齐。解析沿用既有规则：允许包住整个JSON的一对代码围栏，不从混合说明文本中提取JSON。

|模型 / 条件|请求失败|不可解析JSON|原生类型错误|类型对但答案错|答案正确|合计计划|
|---|---:|---:|---:|---:|---:|---:|
|DeepSeek 控制|0|0|2|4|26|32|
|DeepSeek 明确类型|0|0|0|4|28|32|
|Kimi 控制|0|1|20|1|10|32|
|Kimi 明确类型|2|0|0|5|25|32|

本轮没有截断、pending或未尝试记录。类型错误均为字符串，但错误类别按互斥顺序归类：落入“类型错误”不意味着字符串内容在转型后一定正确。类型端点只检查array外层，正式答案仍检查所有元素。

|Kimi|number|5 / 24；4|22 / 22；17（另2次失败）|

## 用同题配对衡量收益和用量

配对键为模型、题目、重复编号，仅保留双方均返回；不能用不同返回数量的全组总token直接算节省率。

|模型|有效 / 缺失配对|正确次数|改善 / 退步|配对总token|总token变化|每个正确答案token|
|---|---:|---:|---:|---:|---:|---:|
|DeepSeek|32 / 0|26 → 28|4 / 2|7,785 → 9,085|增加16.7%|299.42 → 324.46|
|Kimi|30 / 2|9 → 25|16 / 0|9,820 → 10,796|增加9.9%|1,091.11 → 431.84|

“每个正确答案token”是配对总token除以该侧正确次数，包含答错消耗，使用同一批配对。Kimi该比值下降60.4%，DeepSeek上升8.4%。**前者不等于每次请求节省60.4%，更不是已验证的账单或自动修复成本节省。** 它没有纳入失败请求未知用量，也没有为输入、输出及缓存token分别定价。

按16个题ID聚类、2,000次bootstrap的95%描述区间如下；重复不是独立新题，同家族参数题也可能相关，没有多重比较校正。

|模型|正确率差（百分点）|原生类型合格率差（百分点）|配对总token增加|
|---|---|---|---|
|DeepSeek|+6.25；[-9.38, +21.88]|+6.25；[0, +18.75]|+16.70%；[+12.97%, +20.44%]|
|Kimi|+53.33；[+30.00, +73.33]|+66.67；[+43.74, +86.67]|+9.94%；[-1.99%, +20.71%]|

类型配对为DeepSeek 30→32、Kimi 10→30。Kimi的20次类型端点改善包括19次字符串错误和1次不可解析JSON，并非20次字符串修复。区间描述这组任务，不证明总体优势或等价性。

## 原始案例：改善、退步与缺失

以下均可在[run.json](../../examples/token-efficiency-v4/run.json)中按record ID检索；是运行后的解释性选例，不增加样本。

- **类型本身挡住正确答案。** Kimi，`v4-generated-macro_f1-001`第1次：#18的answer为字符串`"0.799798"`，#19为数值`0.799798`。参考约0.7997977755，两者文本数字一样，但只有后者符合数值答案要求。数组排序题第1次，#51→#49也从字符串`"[\"a\",\"q\",\"m\"]"`变为真正数组`["a","q","m"]`；DeepSeek同题#52→#50同样改善。
- **类型和运算同时改变。** Kimi，`v4-generated-macro_f1-004`第2次：#3为`"0.726990"`，#4为`0.727089`，参考约0.7270893566。此例不能把全部质量改善归结为“只是去掉引号”。
- **正确类型也会算错。** DeepSeek，`v4-generated-macro_f1-003`第1次：#90原答0.716942149正确；#89加提醒后答0.6773626562错误。两边都是number，错误来自计算。另一退步是Bayes第6题第2次#41→#44，0.409340变为0.409339，后者误差超过既定1e-6容差，不能事后放宽评分。
- **可读文字不等于可解析输出。** Kimi #118先写多段解释再给代码块，即使末尾数值合理，也不符合现有完整响应解析规则；#119给出完整JSON代码块后判对。该改善属于输出可解析性，未做二次提取。
- **缺失不是错误答案。** Kimi明确类型组#66（Bayes第2题、第1次）与#88（Bayes第3题、第2次）网络失败。对应控制#67是字符串错误、#85正确；剔除这两对后，控制正确数由全组10降为配对9，总token由10,423降为9,820。两次失败均保留，未归因于提示语本身。

## 多维度结果

|维度|DeepSeek 控制 → 明确类型|Kimi 控制 → 明确类型|
|---|---|---|
|Bayes正确 / 返回|12/12 → 11/12|4/12 → 10/10（实验组另2次失败）|
|macro-F1正确 / 返回|8/12 → 9/12|0/12 → 7/12|
|数组任务正确 / 返回|6/8 → 8/8|6/8 → 8/8|
|两次均正确任务 / 两次均返回任务|12/16 → 13/16|5/16 → 10/14|
|两次原始解析答案完全相同 / 两次均可解析任务|12/16 → 9/16|10/15 → 9/14|
|返回延迟中位数|1,175 → 1,160.5 ms|3,966.5 → 3,817 ms|
|返回延迟P90|1,446.7 → 1,611.8 ms|5,531.5 → 6,279 ms|

“完全相同”检查解析答案的类型与值，微小小数变化也可能不同；不是语义稳定性。延迟不包含网络失败耗时，且服务负载、缓存、顺序未完全受控，不能据此判推理速度提升。

数值误差敏感性仍保留原始分母：DeepSeek两组均24条number题返回，≤1e-6均20条；放宽到1e-4分别21、23条。Kimi控制24条返回只有5个有限数值答案，其中4个≤1e-6；明确类型22条返回均为数值，其中17个≤1e-6。**不能仅比较剩余有限数值子集的误差中位数就断言算术能力提高**，两组进入该子集的条件不同。正式成绩始终使用1e-6。

## 解释边界与复核

本轮只验证了16道已知家族的新实例，每题两次、一次服务时间窗口。题型来自前轮失误观察，提示修改也可能改变计算路径，不是对类型错误的纯机械修复。没有比较强制Schema、自动转型、二次修复或真实业务吞吐；没有预设可用性门槛。明确类型组返回没有错型，不代表今后永远不会错型。

原始字节SHA256、执行源码哈希与版本区分见[provenance.json](../../examples/token-efficiency-v4/provenance.json)：执行程序版本0.5.0、发布版本0.6.0。原始文件不重写；分析可以离线重算。所有126条返回重判，类型互斥分类合计、逐组token、配对分母均复核；66项离线测试覆盖旧研究与本轮证据重现。

```bash
python -m peerlab analyze-efficiency examples/token-efficiency-v4/run.json --output runs/v4-recheck
python -m unittest discover -s tests -v
```

下一步值得验证的假设是：固定严格拒绝规则的Schema或修复机制，能否进一步提高每单位用量的正确交付。它尚未执行，不能提前记成当前收益。观点文章：[把token预算花在可用答案上](../opinions/types-and-token-budget.md)。
