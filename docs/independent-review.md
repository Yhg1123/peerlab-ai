# 第四组：先独立求解，再进行审稿

首轮观察提出的问题：审稿模型如果只看到候选答案，会不会直接认可其中错误的算术？扩展协议提供一个可复现的对照，不预设它一定有效。

`--protocol independent` 在 classic 的三组上新增 `peer_independent`。两模型先独立作答，之后普通互审只看到任务与候选答案，先解后审额外看到审稿者**在候选出现前的同次 baseline**。不重新求解，不发送客观参考答案。

每个新条件每个作者增加一次审稿、一次修订，两作者总计14次调用/题。三个修订条件从同一份 baseline 分叉，不从其他修订条件继承答案。记录的 `dependencies` 可追踪每次修订使用了哪份候选与审稿。

审稿者之前的独立解答如果请求失败或截断，对应新条件跳过，不悄悄退化为普通互审。两份候选也都可能错误，提示词要求核验冲突点，不能把自己的旧答案当作标准答案。

```bash
# 完全离线预览调用数、输出上限、题库 hash；不读取API客户端
python -m peerlab run --protocol independent --limit 3 --max-calls 42 --dry-run

# 明确执行付费请求，使用一个新输出目录
python -m peerlab run --protocol independent --limit 3 --max-calls 42
```

默认依然是 classic，原有命令与3题/30次调用预算保持兼容。旧 schema_version=1 的记录也能生成报告；新记录使用 schema_version=2。

新条件改变了两点：审稿上下文增加自己的独立解答，审稿指令增加比较两份推导的要求。因此差异只能归于这一整套干预，不能单独证明锚定偏差的因果机制。调用次数相等也不等于token、延迟或费用相等。
