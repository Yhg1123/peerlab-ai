# 怎样阅读多维度实验报告

v0.4引入token-efficiency-v2，保留旧v1命令和数据。新增条件compact_evidence要求模型先给简短可核验依据、再给answer；它是新的响应策略，不是单独研究思考或字段顺序。正式方案见[24题执行前方案](studies/token-efficiency-v2.md)。

## 先确认三个分母

报告中的“正确/返回/计划”，例如18/47/48，表示计划48次、有47条可用响应、其中18条答案通过。准确率18/47描述返回后的质量；交付正确比例18/48描述计划请求实际交付正确结果的比例。剩下1次可能是网络失败，不能算正确，也不能把它的未知用量记成零。

“配对”要求同一模型、题目、重复编号，两种回答方式都返回。例如一边47条、一边48条，比较只取匹配的47对；节省比例必须同时排除缺失题的左右两端用量。不同条件的完整汇总不能直接拿来算配对节省。

24题各运行两次，得到48个回答，不等于48道独立题。稳定性和重采样区间都以题目为单位处理这种关联。报告中的分类小组还有更少的题，不应用它们发布能力排行榜。

## 输出的四层检查

| 层次 | 检查内容 | 不代表什么 |
|---|---|---|
| 返回 | 请求得到可记录的响应 | 不代表输出完整 |
| JSON合法 | finish_reason=stop且单个对象、含answer、无重复键等 | 不代表字段满足条件或值正确 |
| 契约合格 | 条件要求的字段、类型、依据长度和字段顺序 | 不代表依据真实或与答案语义一致 |
| 答案正确 | 按冻结的参考和误差判answer | 不代表解释内容正确 |

“契约合格且正确”将后两项同时要求，适合了解程序能否按约定消费答案。旧answer评分仍保留，避免新增指标悄悄改写历史成绩。完整单段JSON代码围栏允许，多个块和额外散文拒绝。

evidence的80字要求由Python字符串长度检查，即Unicode码点数量，包括标点；这不是供应商token计数。报告不试图从文字长度猜token，更不让另一个模型主观评分来替代固定规则。

## 每个维度能回答的问题

- **题型分层**：总体平均是否掩盖数值题或代码题的失败？题型由数据集冻结，不按输出事后分组。同一题只有一个类别；生成/人工参考是另一套分组，两套不能叠加求总数。
- **两次重复**：一题是否两次都对，或一次对一次错？只有两次都返回才进入完整任务分母。相同答案需所有重复均可解析；完全相同的错误不算可靠正确。
- **绝对误差**：错误是小数精度偏差还是大幅偏离？放宽至1e-4或1e-2的敏感性分析不改变正式判分，不能把业务精度要求悄悄放松。不同量纲的题不可直接类推。
- **token**：分别统计输入、输出、总量和缺失；按同模型比较。不同tokenizer、缓存和计费权重使跨模型总token比值不能直接代表价格比值。失败请求可能收费。
- **延迟**：成功返回响应的整次请求中位数、P90如何变化？这里不是首token时间，网络、服务端负载与缓存不受控制，超时失败不计入该分布，所以必须一起看失败数。
- **聚类区间**：如果重复抽取这一组题，配对正确率差或节省比例如何波动？这不是新题型或未来版本表现的置信保证。重复抽中的题保留它所有有效配对，2000次抽样使用固定种子；百分位按排序线性插值。

## 输出文件

`analysis.json/md`保留基本条件汇总和整体配对；`dimensions.json/md`增加题型、参考来源、输出契约、耗时、稳定性、误差敏感性和描述区间；`scores.csv`仍是一条请求一行。`report.html`自包含，带可展开的题型和原始响应，离线也可读。HTML中的模型文本统一转义，没有执行模型代码。

```bash
python -m peerlab analyze-efficiency examples/token-efficiency-v2/run.json --output runs/v2-recheck
```

该命令不读取密钥、不调用API；先检查协议、题集哈希、提示词、调度和分数，再生成所有文件。原始JSON的字节哈希在provenance中，CI测试会检查它。文件内部一致性不是供应商签名认证。
